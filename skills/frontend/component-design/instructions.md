# Component Design Instructions

1. Start from a user task and identify the smallest reusable responsibility.
2. Separate layout, content, behavior, data, and domain decisions.
3. Define typed inputs, outputs, events, slots, and controlled/uncontrolled behavior.
4. List default, loading, empty, error, disabled, focus, hover, and responsive states.
5. Specify semantic elements, accessible names, keyboard behavior, and focus movement.
6. Check long content, localization, zoom, touch targets, and reduced motion.
7. Produce a component API, composition examples, state table, and test requirements.

Reject abstractions that exist only to avoid repeating a small amount of local markup.
