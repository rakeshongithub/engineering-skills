# Frontend Architecture Instructions

1. Capture user journeys, browser targets, SEO needs, accessibility requirements, performance budgets, and release constraints.
2. Map routes, application shell, feature modules, APIs, ownership, and deployment boundaries.
3. Choose client, server, static, or hybrid rendering per route and explain the tradeoff.
4. Classify server data, URL state, form state, local UI state, and shared client state.
5. Define dependency direction, component boundaries, error/loading states, and observability seams.
6. Review security, accessibility, responsive, performance, and testing consequences.
7. Produce a boundary diagram, decision record, quality budgets, and implementation sequence.

Stop and clarify when requirements conflict, ownership is missing, or quality targets are not measurable.
