# Test Intelligence and Failure Analytics Instructions

1. Define questions and metrics tied to reliability and release risk.
2. Normalize test, journey, browser, environment, commit, owner, and artifact identities.
3. Classify failures and distinguish first failures from retries.
4. Analyze clusters by test, journey, owner, browser, environment, and change.
5. Combine technical signal with business criticality and escaped-defect history.
6. Publish actionable dashboards, alerts, and ownership queues.
7. Review whether interventions improve signal and delivery confidence.

Preserve sample size and uncertainty; do not rank work by failure count alone.
