# Engineering Examples

These examples show how the skills and workflow recipes combine around realistic engineering problems. They are intentionally small enough to adapt, but include the evidence, decisions, and quality gates expected in a real engagement.

## Examples

| Domain                                      | Scenario                                       | Primary workflow      |
| ------------------------------------------- | ---------------------------------------------- | --------------------- |
| [E-commerce](ecommerce/checkout-feature.md) | Add checkout with idempotent payments          | New feature           |
| [Banking](banking/legacy-modernization.md)  | Modernize a batch payment platform             | Legacy modernization  |
| [SaaS](saas/architecture-review.md)         | Review a multi-tenant analytics platform       | Architecture review   |
| [AI agent](ai-agent/support-triage.md)      | Build a guarded support-ticket triage agent    | Agent development     |
| [Frontend](frontend/README.md)              | Apply frontend architecture and quality skills | Frontend workflows    |
| [E2E testing](e2e/README.md)                | Validate critical journeys end to end          | E2E testing workflows |

## How to Use an Example

1. Replace the domain facts with your system's evidence and constraints.
2. Load the linked workflow recipe and execute each skill in sequence.
3. Preserve the handoff artifacts and decision records between steps.
4. Validate the outputs against the workflow's quality gates.
5. Record assumptions and unresolved questions instead of inventing facts.
